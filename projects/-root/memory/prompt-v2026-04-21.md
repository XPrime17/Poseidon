# CNKB Prompt Rev — 2026-04-21

Ships across all 11 CNKB outbound LLMs (EG + 10 clones). Each prompt grew from ~15.8K to ~18.9K chars.

## Why
Apr 20 call audit surfaced three issues in a single Pickering call (Sean, call_57d1efa072574b9bd6e70152847): agent computed wrong "next Tuesday" date, didn't age-gate a 4-year-old, and deflected booking because parent withheld child name. Root cause for all three was prompt-level.

**How to apply:** When adding/editing outbound prompt rules, grep the full prompt for the lexical family ("confirm", "reach out", "follow up", "call you back") — fixing one instance while another remains undermines the whole intent.

## Changes

### 1. Age gate (Stage 3 — BEFORE asking for name)
| Age | Action |
|---|---|
| 7–14 | Normal Create flow |
| 5–6 | Pivot to **Code Ninjas Junior** (team follow-up only for Junior — appropriate deflection) |
| <5 or >14 | Polite close, no booking |

Age 7 overlaps — default to Create since these are Create-pipeline leads.

### 2. Name-optional booking (Information to Collect)
Parent declines child name → accept. Book using **"the guest"** placeholder. Exact line: *"No problem — I'll lock you in under 'the guest' for now. You're booked for [date] at [time]. The team will grab your kiddo's name when you arrive for the tour."*

Age is still required. Name is preferred but optional.

### 3. Date handling (Stage 5 Rules)
**Removed** the "calculate day-of-week from the date" instruction — LLM was getting it wrong. **Added** SLOTS-deferral: agent finds matching day in `{{SLOTS}}` and reads those dates back, never computes a relative date.

Also updated Fast-Track Booking step 3: if parent uses relative phrase ("next Tuesday"), offer SLOTS matches by day-of-week.

### 4. Booking Autonomy section (new, between Call Management and Identity)
Explicitly forbids "team will reach out to confirm" / "someone will call back to confirm" / "team will confirm your booking" for a tour just booked. Enumerates when staff follow-up IS appropriate: Junior inquiries (5-6), wrong location, callback-requested, out-of-age-range, unanswerable questions. Everything else: you ARE the booking system.

### 5. Stage 6 "need to check calendar" → SOFT HOLD
Replaced "team call you back" deflection with soft hold:
> *"I'll pencil you in for [day, date] at [time] — super easy to swap if it doesn't end up working. If you need to move it, just give us a ring. Sound good?"*

Parent's "sound good" = booking confirmed; agent collects age (and name if offered).

## Post-call schema rev (12 agents — Emma + 11 CNKB)
`appointment_booked` description bumped from 36/65 chars → 390 chars. Now spells out: True if agent stated a confirmed date+time (even with missing name); False if agent deferred to "team will confirm," declined booking, or only tentative.

Why: Retell's post-call judge is a GPT-4.1 pass over transcript steered by the field description. One-line descriptions are fragile on edge cases. Sean's call returned `appointment_booked:false` correctly because the agent's own closing deferred — but sharpening the description reduces misclassification elsewhere.
